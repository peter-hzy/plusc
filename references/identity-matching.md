# 联系人身份匹配

## 1. 目标

确认公开职业资料是否属于目标公司的目标联系人。错误身份会让错误人的经历、职位和联系方式进入名单，因此默认“证据不够就不确认”。

## 2. 证据优先顺序

优先使用：

1. 对方回复过的企业邮箱和本人邮件签名；
2. 公司官网团队页或本人公开职业资料；
3. LinkedIn 资料中同时匹配姓名和当前公司；
4. 活动演讲者页、协会资料或可靠媒体中的姓名、公司和职位；
5. 搜索摘要或只有公司相同的结果，只能作为候选。

V1 尚无历史邮件时，从公司官网和公开职业资料开始。

## 3. 判定规则

### `verified`

需个人与公司双向确认，或两个独立来源同时核对姓名、现任公司与职责，且无冲突。企业邮箱回复及本人签名可形成双向闭环。只有单一官网/个人/LinkedIn页面通常先记 `supported`，不能因URL存在自动升级。该语义闭环由人工核验；CLI保存证据、Claim及审核结果，不自动证明来源独立性或采购权。

### `supported`

- 可靠活动、协会或行业资料同时显示姓名、公司和职责，但公司/本人页面尚未核验；
- 多个独立辅助来源一致，但缺少直接来源。

### `identity_pending`

- 搜索结果返回可能的人；
- 只有姓名相似或只有公司匹配；
- LinkedIn URL 存在但页面无法确认当前任职。

### `contradicted`

- 不同来源显示不同现任公司；
- 姓名与邮箱、本人与公司关系无法同时成立；
- 页面可能属于同名的另一个人。

### `not_found`

- 已完成官网、公开职业资料和合理查询，但没有找到具体负责人。

## 4. 禁止做法

- 不根据邮箱前缀扩写姓名；
- 不根据姓名和域名生成邮箱并标成真实；
- 不因为职位听起来合适就假定其拥有采购权；
- 不把旧职位当作当前职位；
- 不把公司相同但姓名不一致的人认定为同一个人；
- 不使用私人电话、私人邮箱或敏感个人信息；
- 不自动登录、抓取或操作 LinkedIn。

## 5. 联系人和证据的关系

`verified` 或 `supported` 联系人至少应有一条 `Evidence.entity_id=contact_id` 的 A/B 级证据。

`identity_pending`、`contradicted` 和 `not_found` 不能生成 `review_ready`、`approved` 或 `manually_sent` 草稿。可以生成内部研究提示或 `handoff_message`，但不能伪装成已确认负责人。

## 6. 成本控制

联系人优先按中国/亚洲产品、目的地、采购或合作职责选择，小型精品社才优先考虑有相应职责的Owner；不默认联系CEO。任职、职责、采购权、邮箱归属和可达性是不同事实。

没有个人姓名但有官网合作入口时，可用contact_role=handoff记录部门/公司入口，不虚构个人姓名。姓名字段为空允许保留；不能把“Partnerships Team”当真人。

草稿outreach_contract.recipient_kind只能由来源核验为person/department/company，缺依据为unknown；邮箱前缀不能证明个人归属。验证返回accept_all/unknown不升级为valid；API找到邮箱也不自动证明适用营销联系依据。

同一联系人不要反复查询同一来源。记录：

- 已经搜索过什么；
- 哪些来源没有结果；
- 哪些来源受限；
- 为什么值得进一步人工检查。

找到直接证据后停止继续堆叠弱证据。找不到时保留未知，比错误匹配更有价值。
