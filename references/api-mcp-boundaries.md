# API 与 MCP 边界

## 第一阶段

API/MCP 只做窄动作：搜索或读取公开来源、提取结构化字段、写入本地 CSV/Excel、保存草稿、读取用户主动提供的回复。业务判断、证据分级和停发决定仍由 Skill 和人工完成。

## 后续接入顺序

1. 本地文件与表格字段校验；
2. 公开网页/搜索读取；
3. Gmail 或 Outlook 草稿创建（只写草稿，不直接发送）；
4. 官方允许的内容平台数据接口；
5. 在明确授权、速率限制、审计日志和人工确认后，评估其他系统。

不要把“有 API”理解成“可以自动获客”。每个连接器要定义输入、输出、失败、限速、权限和撤销方式，并保留来源 URL 和执行时间。

## MCP 工具合同

每个工具只完成一个动作，建议带：`request_id`、`actor`、`scope`、`dry_run`、`source_urls`、`observed_at`、`confidence`、`requires_human_approval`。涉及写操作时默认 `dry_run: true`，人工确认后才允许执行。

## 不做的捷径

不使用 Cookie/密码模拟 LinkedIn，不批量加人或自动私信，不绕过验证码和访问控制，不抓取非公开数据，不购买无法审计来源的个人联系方式，不让模型直接调用发送工具。
